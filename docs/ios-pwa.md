# iOS: что нужно знать до написания кода

## Push

- Работает с iOS 16.4+, **только если приложение добавлено на домашний экран**.
  Вкладка Safari пуш получить не может, даже с выданным разрешением
- В ЕС работает. Apple убирала home screen web apps в бете iOS 17.4 в феврале
  2024 и вернула через три недели. Статьи, утверждающие обратное, устарели
- Все браузеры на iOS используют WebKit, поэтому Chrome на iPhone ведёт себя
  так же, как Safari. Инструкция пользователю: **Safari → Поделиться → На экран «Домой»**
- Нет автоматического баннера установки, нет события `beforeinstallprompt`.
  Подсказку про установку рисуем сами
- Разрешение запрашивается только по жесту пользователя и только после того,
  как приложение открыто в standalone-режиме. Порядок в онбординге:
  установить → открыть с иконки → объяснить зачем → кнопка → системный запрос
- Отказ в разрешении окончательный: повторно запросить нельзя, только через
  системные настройки. Поэтому перед кнопкой обязателен экран с объяснением
- Endpoint подписки протухает (offload приложения, переустановка). При ответе
  404/410 удаляем строку из `push_subscriptions` и просим переподписаться

## Чего нет и не будет в обозримом будущем

- Запланированных локальных уведомлений — отсюда ADR-001, сервер шлёт всё сам
- Background Sync и Periodic Background Sync — фоновой досылки не будет.
  Отложенные записи отправляем при следующем открытии приложения
- Автоматических промптов установки

## Проверка standalone-режима

```js
const isStandalone =
  window.matchMedia('(display-mode: standalone)').matches ||
  window.navigator.standalone === true;
```

Если `false` — показываем инструкцию по установке, а не кнопку уведомлений.

## Манифест и иконки

- `display: "standalone"`, корректные `start_url`, `scope`, `theme_color`
- Иконки 180×180 (`apple-touch-icon`), 192, 512 и 512 maskable
- Splash-экраны для iOS задаются отдельными `apple-touch-startup-image` под
  каждое разрешение. Необязательно, но без них при запуске мигает белый экран

## Прочие грабли

- Хранилище PWA на домашнем экране **отдельное от Safari**. Отсюда вход по коду,
  а не по ссылке из письма (ADR-002)
- Квоты на хранилище жёстче, чем в Chrome; на много фотографий в кеше не рассчитывайте
- `safe-area-inset-*` обязательны, иначе нижняя кнопка уедет под индикатор Home
- Safari масштабирует страницу при фокусе на input с `font-size` меньше 16px
- Тестировать только на реальном устройстве. Симулятор и десктопный Chrome
  DevTools по пушам врут

## Что проверить руками перед релизом

1. Установка с нуля на чистом iPhone
2. Запуск с иконки: нет адресной строки, есть иконка и название
3. Разрешение на уведомления выдаётся
4. Пуш приходит при **полностью закрытом** приложении
5. Тап по пушу открывает нужный экран, а не главный
6. Вход по коду не выкидывает из standalone
7. Приглашение по QR: сканируем камерой на втором телефоне, проходим
   регистрацию, питомец появляется сразу
