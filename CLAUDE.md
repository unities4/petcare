# PetCare — контекст проекта

PWA для совместного ухода за питомцем. Несколько человек ведут одного питомца:
отмечают кормления, симптомы, лекарства, прививки, визиты к врачу. Push-напоминания.

Основная платформа — **iOS Safari, установленный на домашний экран**. Всё решается
исходя из этого; десктоп и Android идут бонусом.

## Обязательное чтение перед работой

- `docs/product.md` — сценарии, границы MVP, что осознанно НЕ делаем
- `docs/data-model.md` — схема, правила RLS, модель ролей
- `docs/decisions.md` — принятые решения и причины (ADR). Не переигрывай их молча:
  если считаешь решение неверным — скажи и обоснуй, но не меняй код в обход
- `CHANGELOG.md` — что уже сделано и в каком порядке

## Стек

- Vite + React + TypeScript, `vite-plugin-pwa` (Workbox), TanStack Query
- Supabase: Postgres + RLS, Auth (email OTP), Storage, Edge Functions (Deno)
- Планировщик: `pg_cron` + `pg_net` → Edge Function → Web Push (VAPID, `web-push`)
- Хостинг фронта: любой статический (Vercel / Netlify / Cloudflare Pages)

## Жёсткие правила

1. **Миграции только вперёд.** Изменение схемы = новый файл в
   `supabase/migrations/` с меткой времени в имени. Уже применённые файлы не
   редактируем никогда. В конце каждого файла — закомментированный блок `-- DOWN:`
   с SQL для отката.
2. **RLS включён на каждой таблице.** Таблица без политик = баг. Права проверяются
   в базе, а не в UI. UI лишь прячет кнопки.
3. **Никаких прямых запросов к `pet_members` на запись из клиента.** Членство
   меняется только через RPC (`accept_invitation`, `remove_member`).
4. **Ключ пользователя — `user_id`, никогда не email.** Email — один из контактов
   в `user_identities`. Позже добавятся телефон и Telegram.
5. **`id` событий генерируются на клиенте** (`crypto.randomUUID()`) — это даёт
   идемпотентность при ретраях и задел под офлайн-очередь.
6. **Время — `timestamptz`.** Таймзона питомца хранится в `pets.timezone` и
   используется для расчёта напоминаний. Не полагайся на таймзону устройства.
7. **Секреты только в Supabase Secrets / переменных окружения.** VAPID private key,
   service role key и ключи платёжного провайдера никогда не попадают на клиент.
8. **Лимиты тарифов проверяются в базе** (триггеры), а не только на фронте.

## Рабочий цикл

1. Сначала план: какие файлы затронуты, какая миграция нужна, что проверяем руками.
   Дождись подтверждения, потом пиши код.
2. Одна задача = один коммит = одна запись в `CHANGELOG.md` (раздел `[Unreleased]`).
3. После изменения схемы обнови `docs/data-model.md`.
4. Архитектурное решение — короткая запись в `docs/decisions.md`.

## Проверка на устройстве

Многое из этого невозможно проверить в браузере на десктопе. Перед тем как считать
задачу готовой, проговори, что именно нужно проверить на реальном iPhone:
установку на домашний экран, standalone-режим, запрос разрешения на уведомления,
доставку пуша при закрытом приложении.

## Supabase MCP

Только read-only и только к dev-проекту. Смотреть схему, проверять применение
политик, выполнять select — да. Менять данные или схему через MCP — нет,
изменения схемы идут файлами миграций.

## Стиль

- TypeScript strict. Типы БД генерируются: `supabase gen types typescript`
- Без лишних абстракций. Это приложение для семьи, а не для миллиона пользователей
- Тексты интерфейса — русский
